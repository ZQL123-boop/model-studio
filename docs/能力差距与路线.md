## 0. 一句话诊断

**"能干活"的底座已经基本齐了**（18 个工具、Office 三件套、页面体检、并行子代理、锁与多 token、访客隔离）。

**真正缺的是"让用户看得见、管得住"的那一层**：

- 模型自己在脑子里有 plan，**用户看不到**（前端只显示"🔧 已执行 3 步"）
- 文件写完了，**只有一行路径**，没有卡片、不能预览、不能原生打开
- 权限只有"能写/不能写"两档，越界**直接拒**而不是问你
- 技能体系**完全没做**（0 行代码）

最划算的不是再堆工具，而是把这四件事补上。

## 2. 逐类深挖（只写"缺的那部分"）

### A. 流程控制

**A1/A2 是同一个洞**：`AgentState.plan/cursor` 在 `app/agent.py:33-59` 维护，`write_plan` 每轮把进度塞回 system prompt（`build_system`），所以**模型自己知道自己在第几步**。但：
- SSE 只推 `{t: 文本}` / `{step: {...}}` / `{done}`，**没有 plan 事件**（`app/main.py` agent_stream）
- 前端只渲染"🔧 正在 xxx（已 N 步）"（`static/app.html` agent 流处理段）
- 结果：**用户看不见计划，也看不见哪一步卡住**

**A3**：`goals.json` + `set_goal/list_goals` 只解决"存目标"，`persona` 让模型每轮先 `list_goals`。缺的是状态机（待办/进行中/暂停/阻塞）和触发（谁能唤醒它）。scheduler 目前只发通知，不唤起 agent。

**A4**：`_CANCEL[req_id]` 是"整轮任务"级别的取消；`spawn_agents` 内部用 `asyncio.gather`（`agent.run_task`），**没有给每个子任务留 id**，所以停不了单个。

**A5**：`data/agent_sessions/*.json` 只被 `GET /api/agent/sessions` 列出（`main.py:469`），前端连入口都没有。

### B. 上下文与记忆

**B1 最扎心**：`agent.compress()`（`app/agent.py:184-214`）把早期 tool 结果**原地截断成前 200 字 + "…（已压缩）"**，原始字符串直接丢了。截断后模型只能"重新调工具"，用户更没法还原。

**B2/B3**：`data/chat_history.jsonl` 是完整落盘的（含耗时、模型名），所以搜索和导出**只差两个接口 + 一个输入框**，成本极低。

**B4**：`main.py` 里 13 处 `usage` 只是把上游返回的 usage 透传给客户端，没有累计。而且本地 llama.cpp **没有 prompt cache 命中率接口**，这项只能记"token 数 + 时延 + 首字时间"。

### C. 技能体系（差距最大）

全项目 `skill` 关键字 **0 次命中**。当前"能力"= 固定 18 个工具 + 一段 persona 文本。想加能力只能改 `tools.py` 重启。

三件事要一起做才有意义：**目录规范（SKILL.md）+ 按需注入（只把摘要进 prompt，命中才读全文）+ 导入/导出（Git/文件夹）**。

唯一擦边的是 `notes.md`（用户手写的长期背景，`memory.notes_as_system()` 注入），性质是"记忆"不是"技能"。

| 项 | 实测 |

| matplotlib / plotly / seaborn | ❌ 都没装 → **"用图表展示"这类需求目前根本做不到**（只能写 HTML/SVG 或调 `generate_image` 画假图） |
| LibreOffice | ❌ `/Applications/LibreOffice.app` 不存在 → `convert_to_pdf` 直接返回"需要 LibreOffice" |
| node | ✅ 22.22（`~/.workbuddy/binaries/node/...`，但 run_bash 的 PATH 里没有） |
| pnpm | ❌ 没装 |
| MCP | ❌ 无客户端 |

另外 `formulas` 库已经在，**"重算 Excel 公式并核对"其实可以立刻做**（不用等 LibreOffice）。

### E. 自诊断 / 自愈

- E3/E4 是现有亮点：`design.check` 会抓 console 报错、资源加载失败、7 类布局问题，每条带选择器和像素数值。
- E1 完全没有：`_denied()` 只是**规则拒绝**（敏感文件名/后缀/目录），不是"诊断 + 修"。
- E2 半有：`agent.py:158` 用结果前缀 `[错误]/[拒绝]/[超时]` 粗分失败，`run_bash` 30 秒超时会 kill。但"非零退出码 vs 被信号杀 vs 沙箱拒绝"没有分开报，用户看到的都是"失败"。

### F. 权限与安全

现状是**两档**：只读（`WRITE_PROTECT=True` 时拒绝覆盖）／工作区可写（`_write_roots()`）。`~/Projects` 下可写，改前自动备份到 `.ms_backup/`，**没有删除工具**（`move_file` 是唯一破坏性操作）。

三档里的"完全访问"没有；越界是**硬拒**（`[拒绝] 路径不在可写范围`），不是"问你一句"。

额外加分项（A–H 没提但已有）：门禁密码、多 token（可单发/单禁）、访客 persona 隔离（主人记忆永不进公网对话）。

### G. 输出形态

G1–G4 都有，**G5 没有**：回答里给的是 `/Users/.../app.py` 纯文本，不是可点的 `path:line`。

### H. 组合技

H1–H4 全靠 persona 里的流程段落（"先本地再联网""改完必须 check"），**没有可复用的工作流模板**，也没强制"必须带来源链接"。

H5 工具已经有了（`spawn_agents`），缺的是"怎么自动判断该拆几个、怎么汇总"的模板。

## 4. 明确不建议做

1. **A3 全自动推进**：本地 30B 无人值守跑多步，失败模式是"安静地做错"，比不做事更糟。折中：只做"到点提醒 + 一键继续"。
2. **A5 会话分支**：你现在是单人使用，分叉价值远小于维护成本。
3. **D5 MCP**：等真有第二个数据源要接再说。
4. **把 18 个工具再拆细**：persona 已经 4200 token，再加工具会挤掉推理能力。

## 5. 三个里程碑

**M1（1 周）· 看得见**
计划面板 + 交付卡片 + 历史搜索/导出 + pandas + 行号链接
→ 验收标准：随便给一个多步任务，全程能看到"第几步、改了哪些文件、成品在哪"。

**M2（2–3 周）· 管得住**
批准门 + 子任务取消 + 压缩可回滚 + 权限三档/越界询问
→ 验收标准：跑偏能当场拦住；压缩后仍能翻出原文；越界操作会先问。

**M3（1 个月+）· 会复用**
最小技能系统（`skills/` + list/use）+ 把 H1–H4 四套组合技固化成自带技能
→ 验收标准：一句"按调研模板写份报告"就能走完全流程，不用每次教。
