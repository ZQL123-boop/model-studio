# 训练数据提示词（可直接复制使用）

三份提示词，对应数据生产的三道工序：**扩写 → 标注 → 质检**。
都是拿来喂本地 30B（或任何够强的模型）批量跑数据的，不是给终端用户聊天的。

---

## 一、同义改写（已被验证有效的那个）

**用途**：把少量种子问题扩成多种口语说法，解决"句式单一 → 换个说法就认不出"。
**实测效果**：324 条改写让 OOD 准确率 48.8% → 83.1%（+34 pt）。

```
把下面这句话换 {n} 种说法，要求：
1. 意思完全不变（还是同一个需求）
2. 口语化、长短不一，像真人随口说的
3. 每行一句，不要编号，不要解释，不要引号
4. 不要出现工具名（如 read_file、web_search）

原句：{句子}
```

**参数建议**
| 项 | 值 | 原因 |
|---|---|---|
| temperature | 0.9 | 太低会重复同一句式 |
| max_tokens | 400 | 6 句中文足够 |
| n | 5~6 | 再多开始胡说 |
| 每句种子 | 2~3 个 | 覆盖不同槽位（路径/城市/型号） |
| 后处理 | 去重 + 长度 4~60 + 不含工具名 | 见下 |

**必须做的后处理**（否则数据会脏）
```python
lines = [l.strip().lstrip("-•*0123456789.、) ").strip("“”\"'") for l in text.splitlines()]
lines = [l for l in lines if 4 <= len(l) <= 60 and not any(t in l for t in TOOL_NAMES)]
```

**常见翻车**
- 生成句把"工具"说出来了（"用 read_file 读一下…"）→ 模型会学到作弊，必须过滤
- 生成句换了意图（"转成 docx" → "转成 pdf"）→ 标签就错了，抽样 20 条人工看一遍
- 6 句里 4 句几乎一样 → temperature 调高到 1.0，或减少 n

## 二、意图 → 工具标注（加新工具时用）

**用途**：不确定某句话该归哪个工具时，让大模型先标一批，人工抽检。
**注意**：标注结果**必须人工看 20~30 条**，大模型分不清边界时和你的判断不一样。

```
你是数据标注员。下面是工具清单：
{工具名：一句话用途，逐行列出}

请为下面每个用户请求标出最合适的工具名（只能从清单里选一个）。
如果都不合适，写 none。

输出格式（每行一条，用 | 分隔）：
原句 | 工具名 | 一句话理由

待标注：
1. {句子1}
2. {句子2}
...
```

**边界最容易错的四组**（标注时要重点看）
| 容易混 | 区分标准 |
|---|---|
| `read_file` vs `fetch_url` | 本地路径 → read_file；http(s) 链接 → fetch_url |
| `read_file` vs `list_dir` | 要"内容" → read_file；要"有哪些文件" → list_dir |
| `web_search` vs `knowledge_search` | 公开互联网 → web_search；本地算法知识库 → knowledge_search |
| `office` 的多个 action | 转格式 → md2docx；读表格 → read_xlsx；出 PPT → make_pptx |

## 三、质检（批量数据入库前跑一遍）

**用途**：抓"标签对但句子废"的样本（重复、过短、意图漂移、含工具名）。

```
下面是一批训练样本（JSON 数组，每条含 q 和 tool）。
请逐条判断是否有问题，只输出有问题的条目，格式：
{"q": 原句, "issue": "重复/过短/意图漂移/含工具名/语义不通"}

判断标准：
1. 两条句子意思近乎一样 → 后一条标"重复"
2. 少于 5 个字或超过 60 字 → "过短"/"过长"
3. 句子描述的需求与 tool 不匹配 → "意图漂移"
4. 句子里出现工具名或参数名（read_file、query、args）→ "含工具名"
5. 语句不通、像机器拼接 → "语义不通"

没问题就输出 []
```

## 四、怎么调用本地 30B 跑这些提示词

```bash
curl -s http://127.0.0.1:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "default_model",
    "messages": [{"role": "user", "content": "把下面这句话换 6 种说法……原句：读一下 ~/Desktop/笔记.md"}],
    "temperature": 0.9,
    "max_tokens": 400
  }' | python3 -c "import json,sys; print(json.load(sys.stdin)['choices'][0]['message']['content'])"
```

批量化直接看 `training/augment_paraphrase.py`（54 个种子约 17 分钟，17 秒/条）。

## 五、写提示词的三条硬规矩（都是踩出来的）

1. **只让它改措辞，不让它决定标签**。标签继承原意图，永远不会因为"生成器手抖"而标错。
2. **输出格式必须可机读**（每行一句 / JSON 一行一条）。让人去解析自然语言是自找麻烦。
3. **提示词里不要放示例答案**。放了之后模型会往示例上靠，多样性直接掉一半。
